# Settings hinter einer Seam: Prozess-Cache, ein Schreibpfad, laut bei korrupter Datei

Bis zum 22.11.2026 lasen fünf Module (lib.rs ×11, feedback.rs, handoff.rs, history.rs, hotkey.rs) mit `settings::load()` bei jedem Interesse die ganze JSON von der Platte; sieben Tauri-Commands schrieben nach dem Muster load→mut→save. Zwei Folgeprobleme: Zwei zeitversetzte Setter verloren sich still gegenseitig den ersten Write (Last write wins), und eine korrupte `settings.json` fiel über `unwrap_or_default()` still auf Defaults zurück — die kaputte Datei wurde beim nächsten Save kommentarlos überschaltet (Datenverlust ohne Spur, Verstoß gegen die Hausregel „keine stillen Fallbacks"). Der Diktat-Pfad leistete sich zudem 4–5 Platten-Lesungen pro Diktat.

Entscheidung (gegrillt und vom Nutzer bestätigt, 22.11.2026): Der Zustand lebt einmal im Prozess-Cache (`OnceLock<Mutex<Store>>`, lazy beim ersten Zugriff initialisiert — kein init()-Kontrakt, Selftest und Tests laufen unverändert). Das Interface ist zwei Funktionen: `current() -> Settings` (Clone, keine Platte) für Leser und `update(closure) -> Result<()>` als **einziger** Schreibpfad — mutiert, schreibt atomar (Temp-Datei + rename) durch und committet den Cache erst nach erfolgreichem Schreiben; bei Fehler bleiben Cache und Platte alt, der Aufrufer sieht den Fehler statt eines Phantomzustands. Korrupte Datei: Fehler ins Log, Original als `settings.json.corrupt` sichern (vorhandenes Backup wird überschrieben), im Speicher Defaults — die App startet und funktioniert. Fehlende Datei bleibt still (Erststart ist normal). Der Default-Hand-off-Ordner liegt portabel im Dokumente-Ordner statt im hart kodierten Entwicklerpfad. Tests treffen über `install`/`swap` einer Temp-Kopie des Stores (prozesweiter Lock gegen Test-Parallelität) statt gegen die echte Datei.

Abgelehnte Alternativen: Cache im AppState (hätte allen freien Funktionen ein AppHandle injiziert — genau die Signatur-Streuung, die die Seam auflösen soll); typisierte Einzelfunktionen je Feld (~16 Funktionen, wachsen mit jedem Feld — das Interface wäre breiter statt schmaler); debouncetes Sammeln von Writes (Absturz verliert Änderungen, Rennen kämen durchs Zeitfenster zurück).
